0. CRITICAL WORKFLOW RULE — MATERIAL RECEIVED
==================================================

LOCK THIS RULE:

`Material Received` originates in:

SERVICE ENQUIRY.

Example:

ServiceEnquiry.materialReceived = YES / NO

This is the current SOURCE OF TRUTH.

The same value is inherited/displayed downstream:

Service Enquiry
    materialReceived
          ↓
Job Assignment
    read-only inherited value
          ↓
Inspection
    read-only inherited value.

DO NOT create independent editable:

JobAssignment.materialReceived

Inspection.materialReceived

values that can contradict the Enquiry.

==================================================
1. MATERIAL RECEIVED IS NOT MATERIAL REQUEST
==================================================

These are TWO different business concepts.

A)

Material Received = YES / NO

is information captured on the Service Enquiry.

B)

Request for Material

is a transaction containing actual requested material lines:

Code
Description
Batch No
Qty
Remark.

DO NOT implement rules such as:

Material Received = YES
→ block Material Request

or:

Material Received = NO
→ automatically create Material Request.

There is currently NO client evidence supporting either rule.

Material Request creation is driven by:

Inspection
+
Material Required findings

not by guessing the meaning of Enquiry.materialReceived.

==================================================
