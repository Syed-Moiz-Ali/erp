==================================================
0. FINAL PRODUCT DECISION
==================================================

LOCK THIS RULE:

Business users are NOT fundamentally:

HR User
Manager User
Service Manager User
Technician User
Inspector User

They are:

USER ACCOUNT
+
COMPANY MEMBERSHIP
+
OPTIONAL/EXPECTED EMPLOYEE LINK
+
PERMISSION GRANTS
+
SCOPES
+
ORGANIZATIONAL / TEAM / ASSIGNMENT RELATIONSHIPS

The difference between two employees is their ACCESS GRANTS.

DO NOT build future features using:

if (role == Role.hr)

if (role == Role.manager)

if (role == Role.technician)

if (role == Role.serviceManager)

or equivalent.

==================================================

2. PLATFORM SUPER ADMIN
==================================================

Platform/Super Admin may remain a special platform-level authority/account

SUPER ADMIN STATUS MUST NOT BE USED AS A SHORTCUT FOR BUSINESS OPERATIONS.

Being Super Admin must not automatically mean:

can Request Leave

can Complete Inspection

can Complete Service Work

==================================================

==================================================
4. ACCOUNT VS EMPLOYEE
==================================================

Keep these concepts separate:

UserAccount
→ login/security identity.

Employee
→ employment/workforce identity.

A company Employee may or may not have login access.

A user receiving self/assigned work capabilities usually requires a valid,
active Employee link.

Platform/Super Admin may exist without Employee linkage.

Do not duplicate Employee data into access-control tables.

==================================================
13. SCOPE SEMANTICS
==================================================

SELF

Records belonging to the user's linked Employee.

Examples:

My Attendance

My Leave.

ASSIGNED

Operational record explicitly assigned to:

Employee

or eligible team according to module scope policy.

Mostly Services.

TEAM

Records inside a resolved organizational/service-team scope.

ALL

Company-wide records within the active company.

==================================================
14. SCOPE IS NOT A ROLE
==================================================

Example:

Employee A:

hr.leave.records.view
scope = TEAM

does not become "Manager Role."

It simply means the employee is allowed to view Leave records resolved by their
team scope.

==================================================
15. MODULE-SPECIFIC SCOPE RESOLVER
==================================================

Do NOT assume TEAM means the same relationship in every module.

HR TEAM may come from:

employee reporting hierarchy.

Services TEAM may later come from:

ServiceTeam membership/supervision.

Define clean scope-resolution contracts.

The Permission framework supplies the granted scope.

The module determines which records belong to that scope.
