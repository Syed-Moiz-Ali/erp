# Attendance corrections and workforce views

Phase 9 adds local correction requests over immutable attendance events. Employees can submit and cancel requests from a day record. The repository validates the projected event sequence, reason, policy flag, duplicate pending targets, company and employee scope. Managers see only direct reports; permitted HR users see company requests. Reviews recheck the current effective events in a Drift transaction, then store the decision, reviewer and effective day totals. Original punch events are never edited. Attendance details and monthly history read the effective projection. In demo mode decisions remain local; outside demo mode correction operations are queued in the local sync outbox for a future remote contract.

Phase 10 adds scoped Team and All Attendance routes with a joined, paginated local read projection. The query supports date, search, status, department, shift, location and sorting, and exposes live workday status, late/issue flags and pending corrections. Detail routes recheck company and team scope. Dashboard workforce counts are read from this projection. Demo bootstrap seeds varied colleague attendance states without replacing linked users' personal attendance.

The UI uses shared design-system components and English/Arabic localization. The read projection watches local Drift changes and refreshes active status on a minute timer. The database moved to schema version 5 with a migration for correction requests and indexes.

The frontend has no configured remote attendance authority. Production outbox entries intentionally remain pending until a future backend sync contract is implemented. Leave/holiday records and an optional correction submission window are not configured in the current policy model, so the UI does not infer leave or apply a time-window rule. The company clock currently uses fixed-offset timezone handling inherited from the attendance foundation; named-zone daylight-saving support remains future work.
