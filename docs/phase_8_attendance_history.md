# Phase 8 — employee attendance history

1. **Implemented:** Self attendance history, bounded month navigation, typed status filters, monthly aggregates, responsive rows/table, pagination, and reactive day details. Real monthly records also feed the employee dashboard. Frontend only; no backend was created.
2. **Important files:** `domain/attendance_history.dart`, `domain/attendance_repository.dart`, `data/attendance_local_data_source.dart`, `data/local_attendance_repository.dart`, `presentation/bloc/attendance_history_bloc.dart`, `presentation/bloc/attendance_day_details_bloc.dart`, `presentation/pages/attendance_history_page.dart`, `presentation/pages/attendance_day_details_page.dart`, `presentation/widgets/attendance_history_components.dart`, `presentation/widgets/attendance_timeline.dart`, `presentation/widgets/attendance_dashboard_month.dart`. These paths are under `lib/features/attendance/`. Navigation/DI changes are in `lib/app/module_registry/registered_modules.dart`, `lib/app/router/app_routes.dart`, `lib/bootstrap/dependencies.dart`; localized range formatting is in `lib/core/localization/app_formatters.dart` and `lib/l10n/`.
3. **History BLoC:** Business events own startup, month, filter, page and refresh. Immutable state holds query, company current month, data, loading and typed failure. Subscription generation prevents obsolete reads from replacing a newer query. Refresh preserves cached content; authorization failures clear it. Close cancels the watch. No widget database access.
4. **Details BLoC:** Route-owned business BLoC watches one scoped record and its events. Loading, loaded, not-found and failure states remain distinct. Refresh keeps a cached record for retryable failures. Disposing the route cancels the watch.
5. **Repository additions:** `getCompanyAttendanceDate`, `getAttendanceHistory`, `watchAttendanceHistory`, `getAttendanceDayById`, `watchAttendanceDayById`. Summary and status counts are included in the transactional history read, so consumers do not need independent inconsistent queries. There are no employee/company selector arguments.
6. **Monthly summary:** `AttendanceMonthSummary` is an immutable read model with disjoint present/late/working/incomplete counts, completed work/break totals and average completed-day work. Present means completed on time; Late means completed late. Open records contribute to record/status counts, never to finalized duration totals. The four compact visible metrics are worked, present, late and needs attention, accompanied by the completed-only explanation. Attendance rate, absence, leave and overtime are deliberately not calculated without dependable schedule/holiday/leave evidence.
7. **Performance:** SQLite aggregates the entire unfiltered month. Count and page queries apply typed status filters, `LIMIT` and `OFFSET`; default order is newest workday first. `AttendanceHistoryItem` selects cached punches/durations/sync status and only snapshot shift name, timezone and location name. It does not deserialize full policies or load events per list item. The existing composite company/employee/workday index bounds all month reads; EXPLAIN verification confirms indexed access. Details alone load the full immutable snapshot and ordered events. No summary cache or schema migration was needed; schema remains v4.
8. **Month navigation:** Centralized selector crosses December/January correctly. The current month comes from the repository clock and company timezone, never the device's local date. Next is disabled at that month; BLoC also rejects future navigation. Refresh rechecks the current company month. Bounds are half-open: first day inclusive, next month's first day exclusive.
9. **Filters:** Stable typed `AttendanceHistoryStatus` values project the existing engine state; canonical persisted `AttendanceDayStatus` is unchanged. Desktop uses centralized filter chips. Mobile uses a bottom sheet with a presentation-only draft Cubit: Cancel discards, Reset changes the draft, Apply commits to the business BLoC. Active count/clear controls are localized. Filter/month changes reset pagination; a shrunken page falls back to page zero. Month summary remains unfiltered.
10. **Day details:** One repository read model contains the day, saved snapshot, ordered events, read timestamp and lightweight issues. The screen displays date/status, punches, final elapsed/work/break durations, shift/expected/grace/overnight, minimal policy name, saved work location, event validation, individual breaks, and sync/verification notices. No audit IDs, request IDs or coordinates are exposed. Current open records direct users to Today for live totals/actions.
11. **Timeline reuse:** `AttendanceTimeline` is shared by Phase 7's `AttendanceTodayTimeline` wrapper and day details. Ordering and break-session mapping use the existing `AttendanceSummaryCalculator`; no second event renderer or timer engine was introduced.
12. **Overnight:** Records are grouped by stored attendance workday. Punches, timeline and break end times on another date include that date. A previous workday still inside its frozen overnight interval remains Working. A past open record after that interval becomes Incomplete.
13. **Snapshots:** Historical shift, policy, location names, scheduled instants, expected interval, grace and timezone come from saved day configuration. Geofence labels come from saved event validation, including policy allowance; edited live rules never rejudge old coordinates. Wider live configuration is not queried to redefine historical truth.
14. **Incomplete attendance:** Missing punch out and unmatched historical break are visible, with not-recorded endpoints and no invented final durations. Current day remains Working even after scheduled end. Older open workdays past frozen scheduled end are Incomplete. These are read projections, not fabricated absence or new engine transitions.
15. **Sync:** Synced records stay quiet. Pending, failed and rejected appear in rows, table status cells and timeline as appropriate. Details display clear notices. Rejected originals stay intact and advise contacting HR. History refresh is a read, never a new attendance operation; this phase adds no misleading retry or correction button.
16. **Self scope/security:** Every history/date/detail read checks the active account, company module, real linked active employee and `attendanceViewSelf`; wider/team permissions alone do not grant self access. SQL includes company and linked employee even for a known day ID. The repository revalidates identity/permission after the transaction before returning data. Auth-bound route providers reset when context changes. All history/detail routes belong to the existing Attendance module and the same permission gate.
17. **Responsive:** Ten requested widths—360, 390, 430, 600, 768, 900, 1024, 1280, 1440, 1920—are exercised in both languages. Compact and medium available content use tappable rows; expanded content uses `AppDataTable`. Details use `AppOperationalLayout`, central spacing/cards/detail grids and bounded content width. Logical nested navigation selection is fixed centrally. History becomes the employee's third primary mobile destination; Profile remains available through More under the shell's existing three-primary-plus-More policy.
18. **English/Arabic:** All visible text is generated from matching ARB resources, and formatters use the active locale. Language-neutral templates consist only of punctuation and localized placeholders, with explicit RTL arrow localization. Locally bundled Manrope/IBM Plex Sans Arabic are preserved. No packages were added.
19. **RTL:** Month arrows and pagination mirror logically, shell selection resolves the longest route, Arabic ranges point left, and layout uses shared directional components. Names and dates keep natural bidi behavior; no entire page is forced LTR. Badges include text/icons, table/row actions use existing accessible interaction widgets, and shared motion honors reduced animation settings.
20. **Tests added:** 26 real Drift/repository tests cover empty/bounded/unfiltered totals, foreign company/employee/ID exclusion, order/filter/page, December/January, overnight and open status boundaries, frozen data, typed timezone failure, mid-read permission revocation, indexed query plan, watches and issue projections. Five focused BLoC tests cover failures/cache clearing, filtered-empty distinction, stale watch cancellation and details refresh. Twenty-four widget tests cover the full seven-state width/language matrix, missing punch/breaks, multiple breaks, overnight, failed/rejected/pending records, invalid links, retained route owner/filter state, mobile draft Apply/Cancel/Reset active row navigation and current ongoing-break labeling. One shell test explicitly checks module/permission/auth deep links; existing shell/localization expectations were updated for the real destination and neutral templates.
21. **Analyzer:** `flutter analyze` passed with no issues.
22. **Test result:** All 649 tests passed, including four demo attendance seed/workflow tests. Pub get, localization generation, code generation and formatting have completed; the explicit demo release web build passed.
23. **Genuine limitations:** No remote attendance API or sender is configured. Existing company time support is explicit fixed-offset zones; unsupported DST zones fail safely. History is a repository read/watch and does not tick provisional totals—Today remains the single live operational experience. Classification re-evaluates on reads/refresh/local updates. No new physical-device validation is claimed. Historical sync retry is optional and not exposed here. Attendance rate, scheduled-day absence/leave/holiday/payroll interpretation remain deferred.
24. **Phase 9 foundation:** Scoped immutable day detail IDs, typed query/issue projections, preserved event chronology, historical configuration snapshots, existing authoritative repository/state machine/outbox and extensible page-header actions are available for future correction requests. No corrections, approval/team/all-employee views, reports, exports, calendars, leave/holiday/payroll or unrelated ERP module was started. **Stop after Phase 8.**
