# Phase 6 — Attendance core handoff

Frontend only. No server, remote endpoint, synthetic server acceptance, final attendance UI, history UI, corrections, reports or subsequent ERP modules were added. Existing attendance navigation retains its placeholder. The optional debug inspector was omitted; deterministic tests exercise the engine directly.

## Completion report

1. **Architecture.** `features/attendance` separates pure domain services/models, an application action workflow, local data access/synchronization adapters and a presentation-independent BLoC. Repository owns attendance truth. Existing authentication, employees, assigned-configuration discovery, location, results/failures, UUID, connectivity, outbox, BLoC observer and get_it are reused.
2. **Important files.** `domain/attendance_models.dart`, `attendance_state_machine.dart`, `attendance_engine.dart`, `attendance_summary_calculator.dart`, `attendance_context_resolver.dart`, `shift_workday_resolver.dart`, `attendance_location_validator.dart`, `attendance_repository.dart`; `application/execute_attendance_action.dart`; `data/attendance_tables.dart`, `attendance_local_data_source.dart`, `local_attendance_repository.dart`, `device_attendance_location_capture.dart`, `attendance_sync_handler.dart`; `presentation/bloc/attendance_bloc.dart`, `presentation/attendance_localization.dart`; `core/utils/app_clock.dart`, `core/database/app_database.dart`, `core/sync/pending_mutation.dart`, `core/sync/outbox_repository.dart`, `bootstrap/dependencies.dart`, English/Arabic ARBs, `test/attendance_test.dart`, schema v4 and rebuilt web worker.
3. **State machine.** `notStarted → punchIn → working → breakStart → onBreak → breakEnd → working → punchOut → completed`. Repeated break loops are policy controlled. All mutations use this single transition authority; completed blocks all actions. Expected business failures return existing `Result/Failure`, using stable attendance enum names as codes.
4. **AttendanceDay.** Immutable Freezed entity stores tenant/employee, company workday date, frozen configuration, state, punch timestamps, millisecond summary caches, day status, sync status and audit timestamps. Convenience getters expose assignment IDs and cached Duration values. Persisted and returned mutation timestamps are canonical UTC milliseconds. Running caches are a mutation-time snapshot; live duration comes from event calculation at the supplied current time.
5. **AttendanceEvent.** Immutable, append-only normal events carry type, day/tenant/employee, device and optional server instant, persisted sequence, request UUID, source, typed evidence/validation, sync and creation time. `effectiveTimestamp = serverTimestamp ?? deviceTimestamp`, UTC. Plugin Position never enters domain models.
6. **AttendanceEngine.** Pure permission/link/account/employee, transition, timing, scheduling, break, offline, location and integrity decisions; pure summary and available-action calculation. No Drift, Dio, widget or plugin dependencies. Action decisions expose typed failure, warnings, next state, required-location flag and validation.
7. **Repository.** `AttendanceRepository` exposes authenticated self current/watch/date/events/mutate/requeue APIs. Local implementation resolves session and actual employee linkage, tenant/module and active employment, then revalidates inside the mutation transaction. Commands contain no employee/company IDs; `expectedUserId` binds an action workflow to the user who initiated it and is verified, never used to select an arbitrary employee. Linked employee configuration is discovered through EmployeeRepository without granting configuration browsing permissions.
8. **Database.** Schema **4** adds `attendance_days`, `attendance_events` and extends existing `sync_outbox` with optional tenant/request ID for legacy rows, operation status, last attempt and failure code. Original tables/data remain. Migration paths from 1, 2 and 3 are explicit. Unique day key is `(company, employee, workday date)`; a partial unique index permits only one open day per employee/company. Open-day lookup matches the partial index literally; reactive invalidation reads only the newest company/employee day instead of loading history IDs. Events enforce request UUID uniqueness and `(day, sequence)` uniqueness, reference their day, and have timeline/sync indexes. Outbox request IDs have a partial unique index. Attendance instants use UTC epoch milliseconds; workday date is an ISO date key. Snapshot JSON is typed configuration serialization, not generated UI or untyped domain commands.
9. **Durations.** Events ordered by effective instant, persisted sequence, then ID produce elapsed, break, work and open-break durations. Completed days use punch-out forever. Durations never become negative; invalid event sequences produce an inconsistency failure. No tick writes or mutable break counters. Same-time events remain deterministic.
10. **Multiple breaks.** Derived BreakSession entries preserve start/end event IDs and instants. Open breaks contribute through the supplied now. Disabling tracking blocks both break actions. With one-break policy, any prior session prevents another start. Allowed punch-out while on break is a composite terminal event: it closes that break at punch-out, its endEventId is the punch-out ID, and the timeline contains one terminal operation/request. No synthetic break-end request is created.
11. **Overnight shifts.** Company wall time resolves a shift-start workday; through the overnight end, morning belongs to yesterday. An existing open day takes precedence even after the scheduled end or midnight, so 17 Sep 22:05 → 18 Sep 07:01 remains 17 Sep. With no open day, times after overnight end resolve today's upcoming shift; timing rules prevent an accidental early start. Unscheduled punch-in blocks by default; injected `AttendanceEngine(allowUnscheduledWithWarning: true)` supports explicit warning behavior. Grace is inclusive: 09:10 for 09:00 plus 10 minutes is on time, 09:11 is late. Early-in window includes its lower boundary; early-out threshold is scheduled end.
12. **Snapshots.** Full typed immutable Shift, AttendancePolicy and optional WorkLocation records, company timezone, scheduled start/end instants and office/remote mode are frozen at successful punch-in. Rest of that day uses these snapshots, including after assignment removal/configuration edits. Inactive already-assigned configuration remains usable; Phase 5 prevents new inactive assignments. Current employment/login/account authorization is always revalidated and is not frozen.
13. **Location.** Per-action policy requirement determines capture. Workflow never requests GPS for an action that does not require it or already fails preflight. Infrastructure maps existing LocationService Position to typed evidence; permission/service failures become typed attendance failures. Pure Haversine distance uses Earth radius 6,371,000 m, an inclusive radius with tiny numerical tolerance, separate GPS accuracy thresholds and finite-coordinate checks. Evidence must be no older than two minutes, with at most 30 seconds of future-clock tolerance. When policy and location accuracy thresholds exist, both apply. `geofenceRequired` and `geofencePreferred` evaluate radius; outside is allowed only with explicit policy permission. `locationCaptureOnly` and `none` skip radius enforcement but never suppress policy-required capture/accuracy. Explicit remote mode requires remote permission; it waives office geofencing, while per-event capture/accuracy still apply. No final remote-mode UI was added. Validation is persisted with events for audit.
14. **Offline/outbox.** DI selects demo-local authority when the existing demo environment is enabled; demo writes are locally authoritative (`synced`) with no serverTimestamp/outbox and no internet dependency. Default non-demo strategy is production-pending; accepted local mutations create pending events plus generic outbox atomically. Unconfigured backend availability is always false. `ConnectedAttendanceRemoteAvailability` requires both existing connectivity and an injected API probe; a network link alone is not server availability. `notAllowed` blocks unavailable-API mutations, `allowPending` persists pending, `allowWithWarning` additionally warns. No sender is configured/registered/started in the application.
15. **Idempotency.** The action workflow creates one UUID per attempted mutation; it is persisted on event and outbox. Database/repository duplicate checks prevent duplicate events. Retry by operation ID requeues the original payload/UUID and does not insert any event or pretend to send/accept it. Attempt count/last attempt advance only when a configured sender actually attempts delivery. Generic acknowledge cannot delete attendance work without its confirmation path.
16. **BLoC.** AttendanceStarted owns one reactive subscription; refresh recalculates from repository at injected now. Named PunchIn/BreakStart/BreakEnd/PunchOut/Retry events delegate shared workflow/repository. Serialized events plus immediate submission gating prevent queued double taps. Submission keeps ready context/summary/actions; result/stream updates replace repository-derived data. Session/context failures remove stale actionable data. No periodic tick events; subscriptions cancel on close.
17. **Failures/warnings.** `AttendanceFailureCode` covers missing linkage/configuration, inactive account/employee, permission/tenant/module, invalid transitions, timing/scheduling, location/accuracy/evidence, offline, persistence, duplicate requests, retry/sync and unsupported timezone. Pure engine decisions use enum values; repository Failure.code uses their stable names with appropriate existing FailureKind. `AttendanceWarningCode` covers permitted outside location, offline warning mode, late, early-out and explicitly allowed unscheduled days. Exhaustive English/Arabic mappings are in attendance_localization.dart; domain contains no localized strings.
18. **Permissions.** Punch-in requires attendancePunchIn; punch-out attendancePunchOut; both break actions attendanceBreak. Date/event queries require attendanceViewSelf, actual linked employee and company. Roles confer no implicit grants. Manager/HR can act only for their own linked active employee with explicit self permissions. No manual mutation, arbitrary employee action, edit or delete API exists.
19. **Company/timezone.** `AppClock` supplies UTC instants. `CompanyTimeService` is injected; fixed-offset implementation supports UTC/Etc UTC, Dubai, Riyadh, Karachi, Kolkata/Calcutta. Company zone is used even when device zone differs. Unsupported/DST zones return typed unsupportedTimezone. Wall-time DateTime values and date keys represent calendar components; scheduled boundaries are converted back to UTC. Duration math uses instants, never clock strings. Shift planned/fixed break values inform expected work; actual elapsed/break/work totals use actual events, with no invisible scheduled-break deductions. Full IANA/DST support is a deliberate future adapter replacement, not a silent device fallback.
20. **Tests.** Attendance tests cover every state/action matrix, multiple/open breaks, malformed timelines, equal timestamps, server precedence, timing/grace, fixed company offsets, overnight resolution, geofence boundaries/accuracy/outside/remote/staleness, per-action requirements, missing/inactive assigned configuration, permission/account/company/employee isolation, atomic rollback, pending reload, request constraints/retry, demo authority, frozen mid-day changes, read isolation, future-independent event streams, transport failures/rejections/confirmations and BLoC ready/failure/workflows/stream/duplicates/submission/warnings. Dedicated bloc_test cases verify initial ready and missing-configuration states. Deterministic test fixtures provide not-started, working, on-break, completed and overnight examples without populating runtime history. Prior migrations/regression suites remain covered.
21. **Analyzer.** `flutter analyze`: **no issues found**, exit 0. Evidence: `artifacts/phase_6_analyze.log`.
22. **Tests.** **106 attendance tests** pass. Final full regression includes **543 tests**. Evidence: `artifacts/phase_6_tests.log` and `artifacts/phase_6_attendance_tests.log`. Required pub get, gen-l10n, build_runner and formatting passed; schema v4 and compiled web worker were regenerated. Default and explicit demo release web builds also pass.
23. **Limitations.** No actual API/sender, server-time calibration, real server protocol, automatic sync startup, backoff scheduling, cross-device merge/conflict resolution or correction workflow. Rejected events remain the tentative local audit projection with rejected status; engine blocks further actions on a rejected current day, and rejected operations cannot silently requeue. Failed/rejected earlier operations block descendant delivery until explicit retry/resolution. Invalid/mismatched authoritative confirmations roll back metadata/cache changes and retain the operation; reconciliation beyond this safeguard needs the future server contract. Offline device time/location are provisional and cannot provide server-grade anti-tamper security. Unknown/DST timezones are unsupported. No native build/physical GPS/live-browser persistence verification in this phase. Runtime demo employees still need genuine Phase 5 assignments; no unexpected global attendance seed or assignment overwrite was introduced.
24. **Phase 7 contract.** Obtain a fresh AttendanceBloc from get_it, send AttendanceStarted, and render `state.contextStatus`, `currentDay`, `context.events`, `summary`, `actions`, `actionStatus`, `failure`, `warnings`, `lastLocationValidation`. AvailableActions has canPunchIn/canPunchOut/canStartBreak/canEndBreak and per-action decisions with location requirements/block reasons. Use named action/retry events, never infer transitions or access Drift/Dio/GPS from UI. Context.currentTime gives summary as-of time; a lightweight presentation ticker can calculate a fresh pure summary from the same immutable events and AppClock, without writes. Use exhaustive localization mappings for stable domain codes. Company/date changes need an explicit refresh (for example resume/date boundary); no automatic midnight scheduler is claimed.

## APIs

```dart
final bloc = services<AttendanceBloc>(); // factory: caller owns close()
bloc.add(const AttendanceStarted());
bloc.add(const PunchInRequested());
bloc.add(const BreakStartRequested());
bloc.add(const BreakEndRequested());
bloc.add(const PunchOutRequested());
bloc.add(const AttendanceRefreshRequested());
bloc.add(PendingOperationRetryRequested(operationId));

final repository = services<AttendanceRepository>();
final current = await repository.getCurrentAttendance();
final date = await repository.getAttendanceForDate(companyWorkdayDate);
final events = repository.watchAttendanceEvents(dayId);
```

`ExecuteAttendanceAction` orchestrates one optional location capture. Repository execute rechecks actor binding, active session/linkage, policy and all decisions atomically after capture. `AttendanceCommand` is strongly typed by AttendanceEventType, UUID, device instant, expected actor, source, evidence and optional work mode. The repository derives all employment/company/configuration scope itself. Direct command execution is infrastructure/application tooling, not a reason to bypass named BLoC actions in widgets.

`AttendanceSyncHandler` implements existing ModuleSyncHandler. Future integration injects a real AttendanceRemoteSender returning typed request-bound acceptance/rejection and optional server time, then registers the handler with existing SyncCoordinator. Tests alone inject controlled senders. Acceptance updates only sync/server metadata and atomically recalculates day cache; pending event instants otherwise remain device-based. A future backend must enforce UUID idempotency and independent tenant/employee/policy authorization.
