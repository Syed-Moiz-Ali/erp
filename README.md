# Bitlogix ERP - Phase 0

Frontend-only Flutter foundation. The initial route `/design-system` is a temporary internal component preview; `/` is the workspace placeholder. No authentication flows, business modules, servers or backend integrations are implemented.

## Run

Installed SDK: Flutter 3.35.7, Dart 3.9.2. Drift 2.29.0 and Freezed 3.2.3 are compatible with the full test toolchain. `pubspec.lock` records the latest mutually compatible resolution for this SDK and its pinned Flutter test dependencies. There are no dependency overrides.

```sh
flutter pub get
flutter gen-l10n
dart run build_runner build --delete-conflicting-outputs
flutter analyze
flutter test
flutter run -d chrome
# Or on Windows with Visual Studio's desktop C++ workload:
flutter run -d windows
```

The preview runs without API configuration. Future remote repositories can configure `--dart-define=API_BASE_URL=https://your-api.example`; no API call is made during Phase 0.

## Structure

- `lib/bootstrap`: dependency composition, error hooks and BLoC observer.
- `lib/app`: app lifecycle, router, shell and module registry.
- `lib/core`: API client, safe failures/results, Drift database, secure session storage, connectivity, location, sync and logging.
- `lib/design_system`: centralized theme tokens and reusable component families; `design_system.dart` is the public component entrypoint.
- `lib/features`: workspace placeholder and design-system preview. New features add domain, data and presentation layers when needed; no decorative empty folders.
- `drift_schemas`: generated versioned schema snapshot for migration review.
- `assets/fonts`: locally bundled Inter (English) and Noto Sans Arabic with SIL licenses. No runtime font downloads.
- `lib/l10n`: English/Arabic ARB resources and generated typed localizations.
- `lib/core/localization`: locale state, language metadata and formatters.
- `lib/core/preferences`: non-sensitive scalar preferences through repository/local adapter abstractions.
- `tool/drift_worker.dart`: reproducible web database worker source.
- `artifacts/preview_*.png`: font-loaded mobile/tablet/desktop previews generated by widget tests.

## Architecture contracts

UI -> BLoC/Cubit -> optional use case -> repository -> local/remote data sources.

Repositories are the source of truth. Widgets and business BLoCs never import Dio or Drift. BLoC owns business workflows; Cubit is limited to simple presentation state (the preview filters and fields). Add a use case when orchestration, reuse or business invariants justify it.

Local-first features observe Drift-backed repository streams. A future domain write and its outbox mutation must commit in **one database transaction** before reporting success. The shared typed outbox stores mutation IDs, module/entity IDs, operation, payload, creation timestamp and retry attempt count. Mutation IDs deduplicate enqueue calls. Acknowledgment is explicit and should happen only after a remote adapter confirms success. No remote sender or automatic acknowledgment exists yet.

`SyncCoordinator` provides connectivity gating, per-module handler registration, single-flight execution and disposal. Retry/backoff, conflicts, authenticated scheduling and server protocols are deliberately future business work. Connectivity indicates a network link, not server reachability. The coordinator is not started at bootstrap because no sync handlers or authenticated sessions exist.

`Result<T>` separates success from safe `Failure` values. Freezed provides failure equality and immutable JSON-serializable pending mutation models. API errors never expose arbitrary response bodies. Logs contain workflow/event types, not tokens, payloads or employee information. Dio includes request IDs and an access-token interceptor placeholder; refresh and invalidation will live in the future auth repository. Access and refresh tokens use secure storage, never Drift or shared preferences.

## Adding a module

1. Add `features/<module>/domain`, `data` and `presentation` as required by real implementation.
2. Define repository contracts and local data sources; add Drift tables, increase schema version, add explicit migrations and migration tests.
3. Register dependencies in bootstrap (split into feature installers when needed).
4. Add typed GoRouter routes and an `ErpModule` descriptor with ID, name, icon, route, required permissions, navigation group, order and enabled flag.
5. Reuse design-system components and tokens. Register a module sync handler only when the remote protocol is defined.

The registry only supports discovery/navigation. It does not generate screens, enforce security or grant permissions. Its permission set is empty in Phase 0; future auth state must feed both navigation visibility and route guards. Internal preview must be removed or gated before production use.

## Design system

Locale-aware Inter/Noto Sans Arabic typography: display, page title, section title, card title, body large, body, body small, label and caption. Semantic colors, 4-48 spacing, 6/8/12/16 radii, restrained elevation and 150-300ms motion are centralized. Entrance motion respects the platform's reduced-animation preference; skeletons remain static.

Breakpoints: compact <600, medium 600-999, expanded 1000-1439, large >=1440. Compact uses bottom navigation for 2-5 modules and a drawer otherwise; medium uses a rail; expanded/large use a grouped sidebar. Content grids respond to available container width. Tables scroll horizontally in compact layouts. Material 3 is the technical base with a customized theme.

Light theme is active. Theme selection is centralized in `ErpApp`/`AppTheme`; dark mode is not exposed until a full dark semantic palette and component contrast review are implemented. Feature code must never introduce its own palette.

## Platform notes

Native Drift uses application documents storage through `drift_flutter`. Web includes `sqlite3.wasm` (sqlite3.dart 2.9.4) and a worker compiled against the locked Drift dependency. After changing Drift, regenerate the worker:

```sh
dart compile js -O2 tool/drift_worker.dart -o web/drift_worker.dart.js
```

Export schema snapshots after each database version change:

```sh
dart run drift_dev schema dump lib/core/database/app_database.dart drift_schemas
```

Serve WASM as `application/wasm`. See [Drift's official web setup](https://drift.simonbinder.eu/platforms/web/) for browser persistence modes and optional isolation headers. Private browsing can restrict persistence; native targets are recommended where durable offline storage is essential.

Location is a read-only abstraction; it never asks permission at startup. Platform location purpose strings and runtime permission requests belong to the future attendance implementation. Secure storage on Windows uses platform credential protection; web requires a secure context. Native builds require their respective platform toolchains; iOS builds require macOS.

## Validation

Verified on 2026-09-17: `flutter pub get` passed; build_runner passed; `flutter analyze` reported no issues; all 34 tests passed; `flutter build web` passed. Font-loaded mobile and desktop PNGs were visually inspected. Native Android/iOS/Windows builds have not been executed.


Foundation tests cover module visibility/order/duplicate rejection, safe API timeout mapping, JSON roundtrip, actual SQLite outbox deduplication/read/acknowledgment, offline and concurrent sync behavior, and Cubit presentation state. Localization tests cover resource parity, fallback, restoration, ordered persistence, plugin adaptation, validation, failures and formatting. Widget tests walk the preview in English/Arabic at 390, 768, 1280 and 1600 logical pixels, verify RTL and state retention, capture PNGs, and exercise dialogs/sheets/pickers and Arabic at 150% text scale.

See [the localization and RTL contract](docs/localization.md) for language persistence, Arabic typography and adding more languages.

Phase 0 stops here. Authentication and ERP workflows are not started.
