# Bitlogix ERP - Phase 7

Frontend-only, local-first Flutter ERP. Phase 7 adds the real employee Attendance Today experience, shared session AttendanceBloc, page-local display timer, warning-before-mutation confirmation, explicit location UX, truthful sync/retry states and an event-driven today timeline. The employee Dashboard uses real session attendance and no invented monthly totals. Existing UI changes and centralized styling are preserved. See [the Phase 7 completion report](docs/phase_7_attendance_experience.md), [the Phase 6 engine report](docs/phase_6_attendance_engine.md), [configuration handoff](docs/phase_5_configuration.md), [employee handoff](docs/phase_4_employees.md), [dashboard handoff](docs/phase_3_dashboard.md), [shell handoff](docs/phase_2_shell.md) and [authentication handoff](docs/phase_1_authentication.md).

## Run

Installed SDK: Flutter 3.35.7, Dart 3.9.2. Drift 2.29.0 and Freezed 3.2.3 are compatible with the full test toolchain. `pubspec.lock` records the latest mutually compatible resolution for this SDK and its pinned Flutter test dependencies. There are no dependency overrides.

```sh
flutter pub get
flutter gen-l10n
dart run build_runner build --delete-conflicting-outputs
dart format .
flutter analyze
flutter test
flutter run -d chrome
# Or on Windows with Visual Studio's desktop C++ workload:
flutter run -d windows
```

Debug runs enable demo authentication by default. Release builds disable demo fixtures; use `flutter build web --dart-define=DEMO_AUTH=true` for an explicitly designated demo build. Internal `/design-system` requires authentication and demo configuration. Future remote repositories can configure `--dart-define=API_BASE_URL=https://your-api.example`; The current frontend makes no API calls.

## Structure

- `lib/bootstrap`: dependency composition, error hooks and BLoC observer.
- `lib/app`: app lifecycle, router, shell and module registry.
- `lib/core`: API client, safe failures/results, Drift database, secure session storage, connectivity, location, sync and logging.
- `lib/design_system`: centralized theme tokens and reusable component families; `design_system.dart` is the public component entrypoint.
- `lib/features`: authentication, dashboard, employees, shifts, work locations and attendance policies and attendance engine domain/data/application/presentation plus retained Phase 0 previews. New features add domain, data and presentation layers when needed; no decorative empty folders.
- `drift_schemas`: generated versioned schema snapshot for migration review.
- `assets/fonts`: locally bundled Manrope (English) and IBM Plex Sans Arabic with SIL licenses; prior foundation fonts remain bundled. No runtime font downloads.
- `lib/l10n`: English/Arabic ARB resources and generated typed localizations.
- `lib/core/localization`: locale state, language metadata and formatters.
- `lib/core/preferences`: non-sensitive scalar preferences through repository/local adapter abstractions.
- `tool/drift_worker.dart`: reproducible web database worker source.
- `artifacts/preview_*.png` and `artifacts/auth_*.png`: font-loaded visual QA generated by widget tests.

## Architecture contracts

UI -> BLoC/Cubit -> optional use case -> repository -> local/remote data sources.

Repositories are the source of truth. Widgets and business BLoCs never import Dio or Drift. BLoC owns business workflows; Cubit is limited to simple presentation state (the preview filters and fields). Add a use case when orchestration, reuse or business invariants justify it.

Local-first features observe Drift-backed repository streams. A future domain write and its outbox mutation must commit in **one database transaction** before reporting success. The shared typed outbox stores mutation IDs, module/entity IDs, operation, payload, creation timestamp and retry attempt count. Mutation IDs deduplicate enqueue calls. Acknowledgment is explicit and should happen only after a remote adapter confirms success. No remote sender or automatic acknowledgment exists yet.

`SyncCoordinator` provides connectivity gating, per-module handler registration, single-flight execution and disposal. Retry/backoff, conflicts, authenticated scheduling and server protocols are deliberately future business work. Connectivity indicates a network link, not server reachability. The coordinator is not started at bootstrap because no business sync handlers exist.

`Result<T>` separates success from safe `Failure` values. Freezed provides failure equality and immutable JSON-serializable pending mutation models. API errors never expose arbitrary response bodies. Logs contain workflow/event types, not tokens, payloads or employee information. Dio includes request IDs and an access-token interceptor placeholder; refresh and invalidation will live in the future auth repository. Access and refresh tokens use secure storage, never Drift or shared preferences.

## Adding a module

1. Add `features/<module>/domain`, `data` and `presentation` as required by real implementation.
2. Define repository contracts and local data sources; add Drift tables, increase schema version, add explicit migrations and migration tests.
3. Register dependencies in bootstrap (split into feature installers when needed).
4. Register an `AppModule` containing `RegisteredDestination` entries with typed GoRouter routes and `ErpModule` navigation metadata in `registered_modules.dart`. Add centralized route/module constants and localized labels.
5. Reuse design-system components and tokens. Register a module sync handler only when the remote protocol is defined.

The registry controls typed route registration and navigation discovery. NavigationResolver applies explicit grants and company enabledModules to both navigation and route guards. It never grants permissions or generates JSON screens. Frontend guards must be complemented by server authorization when a backend is supplied. The internal preview is gated by authentication and demo configuration.

## Design system

Locale-aware Manrope/IBM Plex Sans Arabic typography: display, page title, section title, card title, body large, body, body small, label and caption. Semantic colors, 4-48 spacing, 6/8/12/16 radii, restrained elevation and 150-300ms motion are centralized. Entrance motion respects the platform's reduced-animation preference; skeletons remain static.

Breakpoints: compact <600, medium 600-999, expanded 1000-1439, large >=1440. The authenticated shell uses up to three priority destinations plus More on mobile, a scrollable rail on medium screens, and a collapsible sidebar on expanded/large screens. Sidebar widths are 248/272px or 80px collapsed. Page content defaults to 1200px; form/details/wide tokens are centralized. Content grids respond to available container width. Tables scroll horizontally in compact layouts. Material 3 is the technical base with a customized theme.

Light theme is active. Theme selection is centralized in `ErpApp`/`AppTheme`; dark mode is not exposed until a full dark semantic palette and component contrast review are implemented. Feature code must never introduce its own palette.

## Platform notes

Native Drift uses application documents storage through `drift_flutter`. Web includes `sqlite3.wasm` (sqlite3.dart 2.9.4) and a worker compiled against the locked Drift dependency. After changing Drift, regenerate the worker:

```sh
dart compile js -O2 tool/drift_worker.dart -o web/drift_worker.dart.js
```

Export schema snapshots after each database version change:

```sh
dart run drift_dev schema dump lib/core/database/app_database.dart drift_schemas
```

Serve WASM as `application/wasm`. See [Drift's official web setup](https://drift.simonbinder.eu/platforms/web/) for browser persistence modes and optional isolation headers. Private browsing can restrict persistence; native targets are recommended where durable offline storage is essential.

Location capture requests permission only after an explicit Work Location form capture or an engine-required Attendance action/location-refresh control. Android foreground location permissions and iOS purpose text are configured. The repository-backed form supports manual coordinates, localized failures, settings/retry actions and measured accuracy. Location services never request permission at startup. Secure storage on Windows uses platform credential protection; web requires a secure context. Native builds require their respective platform toolchains; iOS builds require macOS.

Shell tests cover all ten requested widths in both languages, permission/module gates, deep links, persisted sidebar preference, open-menu localization, branch state preservation and logout reset.

Auth tests additionally cover five email/phone accounts, secure persistence/corruption/expiry, logout failure handling, explicit permissions, DTO mapping, disabled demo configuration, password workflows, protected deep links and all nine requested widths in both languages. Live browser verification was unavailable because no browser connection was present.
